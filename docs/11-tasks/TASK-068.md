**OBJECTIVE:**

Turn PERFORMANCE's budgets into evidence over the built system: the query budgets QB-01–QB-17 asserted as query and statement counts in CI on every run, no N+1 on any page, every hot query's plan verified at 1x, 10x and 100x by PERFORMANCE §12's procedure, the bounded checks PERFORMANCE_TARGETS PFM-01–PFM-20 names run where CI can run them, and the staging measurements — times, load, Argon2id, exports and renditions — prepared as scripts for the operator's run; every miss sent through review to its query, index or budget, never to approved scope.

**WHY THIS EXISTS:**

Every budget, limit and starting value of PERFORMANCE is an assumption until measured (AS-07; TS-09; GAP-017), and AC-23 and DEFINITION_OF_DONE's dimension 7 ask for query evidence, bounded loading and no N+1 regression (REF-059; DOD-13). PERFORMANCE_TARGETS fixes how each target is measured — counts in CI, times on staging — and which form the release-critical set (§§1, 4); two Owner decisions wait on this evidence: the project list's bounded stage filter (GAP-054) and *Beranda*'s receivables position within QB-10 (GAP-060). The staging measurements themselves are the operator's (TASK-079).
