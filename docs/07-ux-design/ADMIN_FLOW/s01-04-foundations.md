## 1. Conventions

- **Identifier families defined here:** UXI (derived interaction requirements), D-UX (interaction design decisions), IP (interaction patterns), J (journeys — `J-` followed by the workflow's own suffix, so J-INV-01 is the journey of WF-INV-01), MSG (message patterns), UXS (mandatory UX scenarios, the Owner's labels of DIR-033 §15). SCR, GL, UXN and D-IA are defined in INFORMATION_ARCHITECTURE; PT, KB, UXV, SLOP and D-DS in DESIGN_SYSTEM.
- **Copy** in `code font` or quotation marks is end-user wording in Bahasa Indonesia and uses the glossary terms of [INFORMATION_ARCHITECTURE §3](../INFORMATION_ARCHITECTURE.md#3-glossary); `{…}` marks a value filled in at run time. The capitalization and punctuation rules are in [DESIGN_SYSTEM §16](../DESIGN_SYSTEM.md#16-copy-and-formatting).
- **Actors** are those of WORKFLOWS §1: OWN, ADM, ADM+ (an Admin holding the separately granted capability), OWN! (Owner only), SYS and BG. "Capability" always means a code of PERMISSIONS_MATRIX §4.
- **Mobile** means the phone patterns of DESIGN_SYSTEM, used below 768 px whatever the input; **desktop** the patterns for 1024 px and wider. Between the two, the tablet rule of [DESIGN_SYSTEM §6](../DESIGN_SYSTEM.md#6-layout-grid-and-breakpoints) applies. Target size follows the input, not the width: a coarse pointer gets touch-size controls and, on a scan step, the scan dock at any width (DESIGN_SYSTEM §6).
- **Examples** — company codes such as ARJ and BTN, names and numbers — are fictional and illustrative ([DESIGN_SYSTEM §1](../DESIGN_SYSTEM.md#1-conventions)).

## 4. Design decisions

Each decision is Level 1 under DIR-033 §13. "Exploration" names the DesainPakeAI brief whose alternatives were compared ([P7_QUALITY_GATE](../evidence/P7_QUALITY_GATE.md#desainpakai-exploration)); a decision without one follows from repository rules alone.

| ID | Decision | Alternatives rejected | Grounds · exploration |
| --- | --- | --- | --- |
| D-UX-01 | The screen shows a command's result only from the server's answer — never an optimistic result | optimistic updates rolled back on failure: a result shown before it is recorded is exactly what HO-01 forbids | HO-01; WORKFLOWS §1 |
| D-UX-02 | While an answer is unknown, the form's inputs are frozen until the intent ends; the user retries or leaves | an editable form keeping the identifier: a changed payload under the same identifier is CONFLICT (CI-05); an editable form with a new identifier: a second effect beside a first one that may have committed | HO-02; CI-02; CI-05 · DPB-16 |
| D-UX-03 | Session expiry is handled in place: the 401 or 419 answer is intercepted, history is cleared, the page is covered by an opaque password dialog, and in-memory input and a pending identifier survive; a full document load only at the absolute limit and on logout | browser storage of drafts: forbidden by WS-07 and WS-08; a full reload at every expiry: loses input silently, against H7-05 | AU-06; AU-07; H7-05; H7-12; HO-02; section 6 |
| D-UX-04 | One automatic retry with the same identifier when a lost connection returns; every other retry is the user's "Coba Lagi" | retry loops: the user has already waited (RY-07), and a background loop hides the unknown state | HO-07; RY-07 |
| D-UX-05 | A compact "Tanggal transaksi" line on every command form, saying whether the date was prefilled or chosen | a full date field on every form: weight for a value that is usually today; no field: hides backdating | HO-08; ST-08; PN-5 |
| D-UX-06 | A duplicate warning is confirmed by a second submission that names the matches it acknowledges, with its reason | a one-click "lanjutkan": cannot name the matches; a block: turns a warning into a block (an Owner decision, DIR-033 §13) | HO-05; CONCURRENCY_IDEMPOTENCY §11 |
| D-UX-07 | Commands on one screen are answered one by one; nothing shows a combined "saved" | one combined result: implies that separate commands commit together | SF-CMD step 8; PX-05 |
| D-UX-08 | The C-10 refusal names only the Admin's own record; the Owner sees what is not started as a derived readiness line, with no new signal | a stored notice to the Owner: a durable record DIR-033 §10-H would route through the channel; naming counters or boundaries: discloses beyond the projection | C-10; NM-03; PN-6 |
| D-UX-09 | The scanner is a keyboard wedge only; camera scanning is not designed for V1 | camera scanning: denied by SECURITY's Permissions-Policy (WS-08) and not promised by V1_SCOPE D-05 | GAP-020; WS-08 |
| D-UX-10 | The confirmation of a correction states what is reversed and what stays, with the reason in the same step | a separate reason screen: one more step for every correction; no statement of what stays: invites the belief that history is erased | BR-CR-01; BR-CR-02; AC-12 · DPB-16 |
| D-UX-11 | On a phone, receiving and dispatch show the purchase's or shipment's lines as a checklist; a scan opens its line, the scan field stays fixed at the bottom within thumb reach, and each line is recorded by its own command | a stepper of five steps per line: slow on the floor; a scan-first sheet with an on-screen keypad: it replaces the device keyboard, which assistive technology and hardware keyboards rely on | GAP-020; SF-SCAN; IP-19 · DPB-09 |
| D-UX-12 | Receiving offers the project reservation inside the same form, sent with the receipt as one command | a separate step after the receipt is saved: AX-04 makes the reservation an optional part of the same action | AX-04; WF-INV-01 · DPB-07 |
