## 1. Conventions

These rules apply to every contract of §2, which names only what a page adds to them. They are Level 1 readings of AICWDF §18.4–§18.6 within ADMIN_FLOW's patterns (TECH-037).

| NV | Rule | Grounds |
| --- | --- | --- |
| NV-01 | **Back** is deterministic: "Kembali" leads to the parent the contract names, from the page's own data, never through browser history alone, which may lead to an unrelated origin. A page with several origins carries its origin as one whitelisted address key and returns there; without it, to the contract's first parent. | AICWDF §18.4; INFORMATION_ARCHITECTURE §11 |
| NV-02 | **Cancel** discards only unsent input, never a committed fact; with unsent input it asks first (MSG-35). The "Kembali" of a confirmation, a reason step or a step-up returns to the form with every input kept. | ADMIN_FLOW §6; IP-08; IP-09; IP-10 |
| NV-03 | **Success** answers in place — the result, its number and the next action (IP-01) —; the page moves only where its contract names a destination, which opens with the result's notice. | IP-01; IP-19 |
| NV-04 | **Errors.** A validation answer stays at its field with the input kept (IP-14); a rejected, conflicting or failed command answers in place, the input kept and a retry carrying the same command identity (IP-01–IP-04); an unknown, an out-of-scope and an Owner-only address show the system page PG-005 with MSG-09, identical for each, and a record in scope without the capability shows it with MSG-10 (IP-21; AZ-11); an expired session signs in again in place, the unsent input kept (IP-11). | IP-01–IP-04; IP-11; IP-14; IP-21 |
| NV-05 | **State.** A list's filters, sort, tab and cursor are whitelisted address keys (§11; IP-18) and come back with Back and reload; a workspace's open section or tab is a key too; a form's unsent input survives the re-login in place but never enters browser history (H7-12); the company context follows §7 of INFORMATION_ARCHITECTURE. | AICWDF §18.6; INFORMATION_ARCHITECTURE §§7, 11; H7-12 |
| NV-06 | **Phone.** The shell's bottom bar and *Lainnya* (INFORMATION_ARCHITECTURE §6.2); a `[desk]` page opens for reading and small tasks without breaking; a form, sheet or dialog takes the screen with its actions in a sticky bar (DESIGN_SYSTEM §11). | INFORMATION_ARCHITECTURE §§6.2, 8; DESIGN_SYSTEM |
| NV-07 | **Outside the shell.** PG-001–PG-004 carry no shell navigation; each link between them keeps the language key `bahasa` (§11; LOCALIZATION). | INFORMATION_ARCHITECTURE §11 |
| NV-08 | **Entries.** An entry exists for an account only when its capability opens the page behind it; a control without its capability is absent, never disabled (AZ-01; H7-03). | AZ-01; H7-03 |

One row per page, grouped as INFORMATION_ARCHITECTURE §8 groups them. *Parent* is the page's place in the product map; *Entry* its entry points; *Back*, *Cancel* and *Success* what the page adds to NV-01–NV-03; *Error · state* the page's error and state behaviour under NV-04 and NV-05; *Phone* its behaviour under NV-06. "—" means the element does not apply.
