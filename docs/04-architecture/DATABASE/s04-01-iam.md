### 4.1 IAM — Identity & Access

| Table | Class | Key columns and constraints | Rules served |
| --- | --- | --- | --- |
| `users` | MD | `public_id`; `name`; `email` UNIQUE on `lower(email)`; `password` (framework-supported one-way hash only, never plaintext or reversible; an unusable password is the hash of an unguessable random value — SECURITY AU-20 c); `is_active`; `deactivated_at/by`; four nullable TOTP fields — the Fortify-native `two_factor_secret` (text, encrypted with the application key), `two_factor_recovery_codes` (text, encrypted the same way) and `two_factor_confirmed_at` (`timestamptz`), and the project's `two_factor_last_step` (`bigint`, the last accepted TOTP time step) — written together when a device is confirmed and cleared together by a reset, a disable or a voiding: CHECK (`num_nonnulls(two_factor_secret, two_factor_recovery_codes, two_factor_confirmed_at, two_factor_last_step) IN (0, 4)`), so confirmation requires a secret and an unconfirmed secret is never stored (C-62) | BR-XC-02 individual identity; never deleted (audit references it); L-34 last active Owner protected; SECURITY AU-16, AU-19–AU-21 (D5, K1, K3) |
| `roles` | CF | `code` UNIQUE (`OWNER`, `ADMIN_OPERASIONAL`; custom roles later, D-01); `is_builtin` | Two launch roles (OB §17) |
| `capabilities` | CF | `code` UNIQUE (e.g. `stock.dispatch`); `authority_class` (`ADM`, `ADM_PLUS`, `OWNER_ONLY`) | WORKFLOWS §4 action families; P5 owns the catalogue |
| `role_capabilities` | CF | PK (`role_id`, `capability_id`) | Capability-based authorization, never role-name checks |
| `user_roles` | SR | PK (`user_id`, `role_id`); `granted_by/at` | One launch role per user in V1 (application rule) |
| `user_capability_grants` | SR | `user_id`, `capability_id`, `granted_by/at`, `revoked_by/at`, `reason`; partial UNIQUE (`user_id`, `capability_id`) WHERE `revoked_at IS NULL` | Separately grantable ADM+ authorities (DIR-024 D-5) |
| `user_company_grants` | SR | `user_id`, `company_id`, `granted_by/at`, `revoked_by/at`; partial UNIQUE (`user_id`, `company_id`) WHERE `revoked_at IS NULL` | Default deny: no active row means no company access (BR-ACC-01) |
| `user_external_identities` | SR | `user_id` → `users` (RESTRICT, required); `provider` CHECK (`google`); `provider_subject` (required — the provider's stable subject, Google's `sub`, at most 255 case-sensitive ASCII characters); `email_at_link` (nullable, display only — never a key, never updated); `linked_at` (required); `linked_by` → `users` (RESTRICT, required — the authenticated account that created the link, in V1 always the holder: CHECK (`linked_by = user_id`)); `unlinked_at` (nullable); `unlinked_by` → `users` (RESTRICT, nullable — the authenticated account whose action performed the unlink, never an operator, a system identity or a placeholder user); `unlink_reason` CHECK (`SELF`, `OWNER`, `DEACTIVATION`, `CREDENTIAL_REISSUE`, `TOTP_DISABLED`, `OWNER_RECOVERY`); CHECKs: while linked, `unlinked_at`, `unlinked_by` and `unlink_reason` are all NULL; once unlinked, `unlinked_at` and `unlink_reason` are both present and `unlinked_by` is NULL exactly when the reason is `OWNER_RECOVERY`; `SELF` and `TOTP_DISABLED` need `unlinked_by = user_id`, `OWNER` and `CREDENTIAL_REISSUE` need `unlinked_by <> user_id` (C-63); partial UNIQUE (`provider`, `provider_subject`) and partial UNIQUE (`user_id`, `provider`) WHERE `unlinked_at IS NULL` (C-64); index on `user_id`; no field beyond these and the routine `id` and `recorded_at` | SECURITY AU-22–AU-24 (D6, K2): the account is found only through `provider_subject`, never by e-mail; one active link per account and per subject; rows never deleted — an unlink fills its three columns once and relinking adds a row, so the rows are the history, and every link and unlink writes its audit event in the same transaction and its security event. Unlink contract: `SELF` — the holder unlinks, `unlinked_by` = `user_id`; `OWNER` — an Owner through `users.manage`, `unlinked_by` = that Owner; `DEACTIVATION` — the account is deactivated, `unlinked_by` = the Owner running the command; `CREDENTIAL_REISSUE` — an Owner resets the account's TOTP, `unlinked_by` = that Owner; `TOTP_DISABLED` — the holder disables TOTP, `unlinked_by` = `user_id`; `OWNER_RECOVERY` — an OWNER_RECOVERY link is used, `unlinked_by` NULL, the unlink's audit event naming the credential link whose issue event names the operator (SECURITY AU-14) |
