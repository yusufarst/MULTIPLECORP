Tidak ada fixed delivery date yang boleh menurunkan kualitas, kelengkapan,
struktur, security, data integrity, UX quality, testing quality, atau
implementation readiness.

Jangan memotong scope atau mempertahankan keputusan lama hanya demi mengejar
tanggal.

2. AICWDF v4.3

YES.

AICWDF v4.3 menjadi governing planning / execution framework untuk arah
MULTIPLECORP ke depan, subject to:

- latest explicit Owner decisions;
- preserved business/domain truth;
- preserved valid data-integrity guarantees;
- preserved valid security/concurrency/audit semantics unless explicitly
  superseded;
- controlled change management and traceability.

Jika AICWDF bertentangan dengan keputusan lama yang hanya merupakan pilihan
planner/technical default, AICWDF + latest Owner intent boleh menggantikannya
melalui controlled amendment.

Jangan menganggap APPROVED berarti immutable forever.

3. P7 VISUAL / IA BASELINE

YES.

Saya mengotorisasi penggantian substantial terhadap visual baseline dan
information architecture P7/APPR-008.

APPR-008 tetap dipertahankan sebagai historical provenance, tetapi bagian UX
yang digantikan harus disupersede melalui approval/baseline baru.

Ramp adalah DESIGN REFERENCE yang memang saya pilih sebagai Owner.

Ramp tidak perlu disalin secara literal.

Yang saya inginkan dari arah Ramp antara lain:

- modern;
- clean;
- professional;
- visually calm;
- lebih mudah dipahami user baru;
- visual breathing room;
- tipografi lebih besar dan lebih terbaca;
- control size yang nyaman;
- whitespace dan section separation yang jelas;
- hierarchy yang kuat;
- progressive disclosure;
- navigasi yang lebih sederhana;
- task-oriented IA, bukan backend/domain-oriented IA;
- lebih sedikit top-level navigation bila memungkinkan;
- hindari duplicate navigation seperti tahap + tab yang menyampaikan hal sama;
- dashboard per role yang mudah dipindai;
- angka/status penting lebih terlihat;
- primary action jelas;
- mobile-first;
- desktop tetap produktif;
- data-heavy screens boleh lebih dense hanya jika memang dibutuhkan;
- lime/accent Ramp boleh digunakan secara accessible, misalnya dark text di
  atas lime, bukan lime sebagai text dengan contrast buruk;
- tetap cocok untuk implementasi shadcn/ui.

Pertahankan pola UX lama hanya bila pola itu terbukti lebih baik atau diperlukan
oleh business/security/accessibility constraints.

Business truth tidak boleh diubah hanya demi visual.

4. ANTI-AI-SLOP VS AICWDF §18.2

Jika aturan anti-AI-slop lama bertentangan dengan AICWDF §18.2, Owner intent
terbaru, atau arah Ramp yang saya pilih, maka:

AICWDF §18.2 + latest Owner UX direction MENANG.

Namun jangan menghapus seluruh anti-AI-slop discipline.

Pertahankan aturan anti-AI-slop yang masih membantu:

- kejelasan;
- konsistensi;
- accessibility;
- professional appearance;
- menghindari decorative clutter;
- menghindari fake metrics;
- menghindari meaningless cards;
- menghindari duplicate actions;
- menghindari UI gimmicks.

Buang atau revisi hanya aturan lama yang memaksa excessive density,
typography terlalu kecil, spacing terlalu rapat, atau menolak visual direction
Owner tanpa alasan business/security/accessibility yang nyata.

10. STRUCTURAL MIGRATION

YES.

Saya mengotorisasi controlled repository/planning structural migration jika
hasil analisis menunjukkan manfaat yang nyata.

Diizinkan antara lain:

- merampingkan bootstrap/entry documents;
- memisahkan history dari current operating context;
- memecah dokumen sangat besar secara modular;
- menambahkan index/aggregation layer;
- menambahkan TOOLCHAIN.md;
- menambahkan AICWDF adoption/mapping document;
- menambahkan execution layer;
- menyiapkan EXECUTION_CONTEXT.md;
- menyiapkan struktur docs/11-tasks untuk P11;

Syarat migrasi:

- jangan hilangkan business knowledge;
- jangan hilangkan historical provenance;
- jangan reset approval history;
- sediakan mapping old → new;
- pemecahan dokumen tanpa semantic change harus dapat diverifikasi;
- semantic changes harus dicatat sebagai amendment/supersession;
- jangan melakukan cosmetic rename/restructure tanpa manfaat operasional;
- repository setelah migrasi harus lebih mudah dipahami replacement agent,
  planning agent dan execution agent.
