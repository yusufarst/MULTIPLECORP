4. PRIORITAS SECURITY — TASK-064
Ada dua dugaan material yang harus diverifikasi.
SECURITY FINDING A — UXH-02
Pada `session-core.ts`, `sameAccount()` membandingkan account hints menggunakan `JSON.stringify`.
Account hints tidak mengandung identifier akun unik.
Risikonya adalah akun B dengan nama, capabilities, dan perusahaan yang identik dapat dianggap sama dengan akun A saat autentikasi ulang.
Ini berpotensi membuat:

* Halaman akun A tetap terbuka.
* Input lama akun A tetap terlihat.
* Pending command akun A dikirim ulang oleh sesi akun B.
* Batas pemisahan akun dalam UXH-02 dilanggar.

PERINTAH:

1. Buat skenario deterministik dengan dua akun berbeda.
2. Berikan nama tampilan, capabilities, dan perusahaan yang sama.
3. Pastikan user ID berbeda.
4. Buat input serta pending command pada akun A.
5. Paksa re-authentication.
6. Lakukan sign-in menggunakan akun B.
7. Pastikan halaman A tidak dapat dilanjutkan.
8. Pastikan input A tidak terlihat.
9. Pastikan command A tidak dikirim ulang.
10. Pastikan tidak ada efek bisnis tercatat atas identitas yang salah.

Jika defect terbukti, lakukan perbaikan sesuai kontrak UXH-02 dan mekanisme defect/CHANGE_CONTROL.
Gunakan identitas akun yang stabil dan berasal dari server. Jangan hanya mengubah fixture agar pengujian tampak berhasil.
SECURITY FINDING B — REAUTH 419
Ada dugaan bahwa setelah respons 419 pada sesi yang masih valid, dialog login ulang dapat menerima password yang salah.
PERINTAH:

1. Reproduksi 419 dengan sesi yang masih valid.
2. Pastikan dialog re-authentication muncul.
3. Masukkan password salah.
4. Verifikasi respons server yang sebenarnya.
5. Pastikan dialog tidak menutup.
6. Pastikan pending command tidak dijalankan.
7. Pastikan halaman tidak dibuka kembali berdasarkan autentikasi palsu.
8. Uji pula password benar dan flow TOTP untuk memastikan jalur sah tetap berfungsi.
9. Uji bahwa guest middleware, redirect, dan interpretasi HTTP response tidak menciptakan false authentication success.

Jika terkonfirmasi, ini defect keamanan blocking.
Jangan memperbaikinya dengan mengabaikan 419, mengubah kode status yang diharapkan, atau melemahkan tes.
SECURITY FINDING C — PG-014 pending command
Verifikasi bahwa input form terkunci saat hasil command belum diketahui, sesuai IP-02 dan kontrak terkait.
Jika terbukti ada celah, perbaiki melalui jalur yang sah tanpa membuat Task baru secara sembarangan.
